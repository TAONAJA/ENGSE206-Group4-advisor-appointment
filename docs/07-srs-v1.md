## 1. Introduction

### 1.1 Purpose
เอกสารข้อกำหนดความต้องการซอฟต์แวร์ (SRS) ฉบับนี้จัดทำขึ้นเพื่อระบุข้อกำหนดทั้งเชิงฟังก์ชัน (Functional Requirements) และไม่ใช่เชิงฟังก์ชัน (Non-functional Requirements) รวมถึงกฎทางธุรกิจ (Business Rules) และขอบเขตการทำงานของ "ระบบนัดหมายเข้าพบอาจารย์ที่ปรึกษา (Advisor Appointment System)" สำหรับใช้เป็นแนวทางอ้างอิงหลักในการออกแบบ พัฒนา และตรวจสอบความถูกต้องของระบบโดยทีมพัฒนาและผู้มีส่วนเกี่ยวข้อง

### 1.2 Scope
ระบบนัดหมายเข้าพบอาจารย์ที่ปรึกษา ครอบคลุมฟังก์ชันการค้นหาและแสดงช่วงเวลาว่าง (Office Hours) ของอาจารย์ที่ปรึกษา, การส่งคำขอนัดหมายพร้อมระบุวัตถุประสงค์และแนบไฟล์ประกอบ, การอนุมัติ ปฏิเสธ หรือขอเสนอเลื่อนเวลานัดหมายโดยอาจารย์, การส่งแจ้งเตือนสถานะผ่าน Email สถาบัน และ Web Notification, การควบคุมเงื่อนไขการยกเลิกล่วงหน้า 24 ชั่วโมง และการบันทึกประวัติการเข้าพบ  
*ระบบนี้ไม่ครอบคลุม:* ระบบจัดการเรียนการสอน (LMS), ระบบลงทะเบียนเรียนหลักของมหาวิทยาลัย, ระบบลาเรียน/ลาป่วยอย่างเป็นทางการ, การเชื่อมต่อ Google Calendar แบบภายนอก, และการส่งข้อความผ่านแอปพลิเคชันบุคคลที่สาม เช่น LINE Notify

### 1.3 Definitions, Acronyms and Abbreviations
* **SRS:** Software Requirements Specification
* **Office Hours:** ช่วงเวลาที่อาจารย์ที่ปรึกษากำหนดไว้ในระบบว่าสะดวกให้นักศึกษาเข้าพบ
* **Pending:** สถานะคำขอนัดหมายที่รออาจารย์ที่ปรึกษาพิจารณา
* **Confirmed:** สถานะคำขอนัดหมายที่ได้รับการอนุมัติเรียบร้อยแล้ว
* **Rescheduled:** สถานะคำขอนัดหมายที่อาจารย์เสนอปรับเปลี่ยนวันหรือเวลาใหม่
* **No-show:** กรณีที่นักศึกษาไม่มาตามนัดหมายที่ได้รับการยืนยันแล้ว
* **RBAC:** Role-based Access Control (การควบคุมการเข้าถึงข้อมูลตามบทบาท)

## 2. Overall Description

### 2.1 Product Perspective
ระบบนี้เป็นเว็บแอปพลิเคชันส่วนกลางที่พัฒนาขึ้นเฉพาะทางเพื่อบริหารจัดการตารางเวลาและการนัดหมายระหว่างนักศึกษากับอาจารย์ที่ปรึกษาในภาควิชา เพื่อแก้ปัญหาการนัดหมายกระจัดกระจายผ่านแชตส่วนตัวหรือโทรศัพท์ และลดปัญหาการนัดหมายซ้อนทับกัน ตัวระบบทำงานแบบ Standalone ร่วมกับระบบบริการยืนยันตัวตน (Identity Service) และระบบบริการส่งอีเมลของสถาบัน

### 2.2 User Classes and Characteristics
* **นักศึกษา / ผู้ขอเข้าพบ (Student):** ใช้งานระบบเพื่อตรวจสอบตารางเวลาว่างของอาจารย์ ส่งคำขอนัดหมาย ติดตามสถานะ และขอยกเลิกนัดหมายล่วงหน้า
* **อาจารย์ที่ปรึกษา (Advisor):** ใช้งานระบบเพื่อระบุช่วงเวลาว่าง (Office Hours) ตรวจสอบรายละเอียดคำขอ อนุมัติ ปฏิเสธ หรือขอเสนอเลื่อนเวลา ตลอดจนบันทึกสรุปผลหลังการเข้าพบ
* **เจ้าหน้าที่ภาควิชา / ผู้ดูแลระบบ (Staff / Admin):** ตรวจสอบภาพรวมการนัดหมาย จัดการข้อมูลการจับคู่อาจารย์กับนักศึกษา และดูรายงานสถิติเชิงภาพรวม
* **ผู้ดูแลระบบ IT (IT Admin):** กำหนดสิทธิ์การเข้าถึง ดูแลความปลอดภัยของบัญชีผู้ใช้และ Audit Trail

### 2.3 Operating Environment
* เว็บแอปพลิเคชันที่รองรับการทำงานบนเว็บเบราว์เซอร์มาตรฐานยุคใหม่ (Modern Web Browsers) เช่น Google Chrome, Mozilla Firefox, Microsoft Edge และ Safari
* ฝั่งเซิร์ฟเวอร์เชื่อมต่อกับฐานข้อมูลเชิงสัมพันธ์ (Relational Database) และระบบ Mail Server สำหรับส่งอีเมลแจ้งเตือนของสถาบัน

### 2.4 Constraints
* โครงงานเพื่อการศึกษาภายใน 1 ภาคการศึกษา โดยจำกัดขอบเขตการจำลองระบบ
* ไม่อนุญาตให้เชื่อมต่อ API ภายนอกที่อาจก่อให้เกิดความเสี่ยงด้าน Data Privacy หรือมีค่าใช้จ่ายเพิ่มเติม เช่น การซิงค์ Google Calendar ภายนอก และ LINE Notify API
* การเข้าพบแบบ Online กำหนดให้อาจารย์เป็นผู้ระบุลิงก์ห้องประชุม (เช่น Google Meet หรือ MS Teams) แบบ Manual ในขั้นตอนอนุมัติ เพื่อหลีกเลี่ยงความซับซ้อนของการผูก API สิทธิ์ระดับองค์กร

### 2.5 Assumptions and Dependencies
* ผู้ใช้งานทุกคนมีบัญชีผู้ใช้ของสถาบันและสามารถเชื่อมต่ออินเทอร์เน็ตเพื่อเข้าใช้งานระบบได้
* อาจารย์ที่ปรึกษามีการระบุและอัปเดตช่วงเวลาว่าง (Office Hours) ของตนเองในระบบอย่างสม่ำเสมอ
* การส่งแจ้งเตือนต้องพึ่งพาบริการ Mail Service ของสถาบันในการกระจายข้อความ

## 3. Functional Requirements

| ID | Requirement | Priority | Acceptance / Verification |
|---|---|---|---|
| **FR-01** | ระบบต้องแสดงช่วงเวลาว่าง (Office Hours) และสถานะพร้อมให้เข้าพบของอาจารย์ที่ปรึกษา เพื่อให้นักศึกษาสามารถเลือกวันและเวลาได้ | Must | ตารางเวลาแสดงผลสถานะว่าง/ไม่ว่างถูกต้องตามปฏิทิน และอัปเดตสถานะทันทีเมื่อมีรายการจอง (ตรงตาม AC-01, AC-02) |
| **FR-02** | ระบบต้องให้นักศึกษาส่งคำขอนัดหมาย โดยระบุวัตถุประสงค์ รายชื่อผู้เข้าพบ (เดี่ยว/กลุ่ม) และแนบไฟล์เอกสารประกอบได้ | Must | นักศึกษากรอก Required Fields ครบถ้วนแล้วกดส่งคำขอสำเร็จ รองรับไฟล์แนบ `.pdf` หรือ `.docx` ขนาดไม่เกิน 10MB และคำขอถูกบันทึกในสถานะ Pending (ตรงตาม AC-03, AC-04) |
| **FR-03** | ระบบต้องให้อาจารย์ที่ปรึกษาสามารถอนุมัติ ปฏิเสธ หรือเสนอวันและเวลานัดหมายใหม่ (Reschedule) พร้อมระบุเหตุผลได้ | Must | อาจารย์เลือกสถานะคำขอได้ถูกต้อง โดยกรณีปฏิเสธหรือขอเลื่อนเวลาต้องบังคับกรอกเหตุผลก่อนกดยืนยัน (ตรงตาม AC-06, AC-07, AC-08) |
| **FR-04** | ระบบต้องส่งข้อความแจ้งเตือนเมื่อมีการสร้างคำขอใหม่หรือมีการเปลี่ยนแปลงสถานะคำขอนัดหมาย ผ่าน Email สถาบัน และ Web Notification | Should | ส่ง Email และแสดง Alert บน Web Notification ภายใน 1 นาทีหลังมีคำขอใหม่หรือสถานะคำขอเปลี่ยน (ตรงตาม AC-09, AC-10) |
| **FR-05** | ระบบต้องรองรับการเลือกรูปแบบการเข้าพบทั้งแบบ On-site (ระบุห้อง/สถานที่) และ Online (ให้อาจารย์แนบลิงก์การประชุม) | Should | ในหน้ารายละเอียดการนัดหมายแสดงสถานที่เข้าพบหรือแสดงลิงก์ห้องประชุมให้นักศึกษาเปิดดูได้ถูกต้อง (ตรงตาม AC-05, AC-06) |
| **FR-06** | ระบบต้องรองรับการบันทึกสรุปผลการเข้าพบของอาจารย์ และจัดทำรายงานสถิติการนัดหมายภาพรวมของภาควิชา | Could | อาจารย์สามารถบันทึกข้อความสรุปหลังนัดหมายเสร็จสิ้นได้ และเจ้าหน้าที่สามารถเปิดดูรายงานสรุปยอดการนัดหมายได้ (ตรงตาม AC-13) |

## 4. Non-functional Requirements

| ID | Quality Attribute | Requirement | Measure |
|---|---|---|---|
| **NFR-01** | Security / Privacy | ระบบต้องจำกัดสิทธิ์การเข้าถึงข้อมูลคำขอ วัตถุประสงค์การเข้าพบ และประวัติการนัดหมายตามบทบาท (Role-based Access Control) | นักศึกษาต้องไม่สามารถเปิดดูข้อมูลคำขอของผู้อื่นได้ และสิทธิ์การจัดการข้อมูลถูกจำกัดตาม Role & Permission Matrix 100% |
| **NFR-02** | Usability | ระบบต้องถูกออกแบบให้นักศึกษาสามารถค้นหาเวลาว่างและสร้างคำขอนัดหมายได้สะดวกและรวดเร็ว | นักศึกษาสามารถค้นหาช่วงเวลาและทำรายการส่งคำขอนัดหมายสำเร็จได้ภายในไม่เกิน 4 หน้าจอ/ขั้นตอน |
| **NFR-03** | Performance | ระบบต้องสามารถประมวลผลและแสดงผลตารางเวลาว่างของอาจารย์ได้อย่างรวดเร็ว | หน้าตารางแสดงผลเวลาว่างของอาจารย์ต้องโหลดข้อมูลเสร็จสิ้นภายในเวลาไม่เกิน 3 วินาที ในสภาวะเครือข่ายปกติ |
| **NFR-04** | Integrity / Business Rule | ระบบต้องควบคุมเงื่อนไขการยกเลิกหรือขอเลื่อนนัดหมายล่วงหน้าตามเกณฑ์ที่กำหนด | ระบบต้องปิดกั้น (Disabled) ไม่ให้นักศึกษากดยกเลิกหรือขอเลื่อนคำขอนัดหมายที่มีกำหนดการเข้าพบน้อยกว่า 24 ชั่วโมงล่วงหน้า |

## 5. External Interface Requirements

### 5.1 User Interfaces
* **Student Dashboard / Booking Interface:** หน้าปฏิทินแสดงตารางเวลาว่าง (Office Hours) พร้อมแถบสีจำแนกสถานะว่าง/ไม่ว่าง และหน้าฟอร์มส่งคำขอเข้าพบที่มีช่องระบุหัวข้อ, รูปแบบการพบ (On-site/Online), รายชื่อผู้เข้าร่วม และปุ่มอัปโหลดเอกสาร
* **Advisor Management Console:** หน้ารายการคำขอเข้าพบ (Pending, Confirmed, Rescheduled, Completed) พร้อมปุ่มเลือก อนุมัติ / ปฏิเสธ / เสนอเลื่อนเวลา และฟอร์มสำหรับระบุลิงก์ประชุมหรือบันทึกสรุปผล
* **Notification Component:** ป๊อปอัปแจ้งเตือนภายในหน้าเว็บ (Web Notification Bell / Banner) แสดงสถานะอัปเดตแบบเรียลไทม์

### 5.2 Software / External System Interfaces
* **Identity Service (Mock / Institution SSO):** อินเทอร์เฟซสำหรับตรวจสอบการเข้าสู่ระบบและระบุสิทธิ์บทบาท (Student, Advisor, Staff, Admin)
* **Institution Mail Service (SMTP):** อินเทอร์เฟซสำหรับส่งข้อมูลแจ้งเตือนไปยังอีเมลสถาบันของผู้ใช้งานเมื่อเกิดเหตุการณ์คำขอใหม่หรือการเปลี่ยนสถานะ

### 5.3 Data Interfaces
* **File Storage:** อินเทอร์เฟซจัดเก็บและตรวจสอบไฟล์แนบโครงงาน รองรับไฟล์ `.pdf` และ `.docx` ขนาดสูงสุดไม่เกิน 10MB ต่อคำขอ
* **Internal Calendar Data Schema:** โครงสร้างข้อมูลตารางเวลาภายในระบบสำหรับจัดเก็บ TimeSlot, สถานะการจอง และการจับคู่ระหว่างนักศึกษากับอาจารย์

## 6. Business Rules

| ID | Rule | Related Requirement |
|---|---|---|
| **BR-ADV-01** | **กฎการยกเลิกและเลื่อนนัดหมายล่วงหน้า 24 ชั่วโมง:** นักศึกษาต้องทำการยกเลิกหรือขอเลื่อนนัดหมายล่วงหน้าไม่น้อยกว่า 24 ชั่วโมงก่อนถึงกำหนดเวลานัด หากเหลือน้อยกว่า 24 ชั่วโมง ระบบจะปิดกั้นการทำรายการผ่านหน้าเว็บ และแนะนำให้ติดต่ออาจารย์โดยตรง (ยกเว้นกรณีอาจารย์เป็นผู้ยกเลิกเนื่องจากภารกิจด่วน) | FR-03, NFR-04, UC-04 |
| **BR-ADV-02** | **กฎการระบุเหตุผลในการปฏิเสธหรือขอเลื่อน:** ทุกครั้งที่อาจารย์ที่ปรึกษากดปฏิเสธคำขอ (Reject) หรือเสนอเลื่อนเวลา (Reschedule) ระบบต้องบังคับให้ระบุข้อความเหตุผลประกอบเสมอ เพื่อความโปร่งใสและให้นักศึกษาเข้าใจเงื่อนไข | FR-03, UC-03 |
| **BR-ADV-03** | **กฎการล็อกช่วงเวลา (Slot Locking):** เมื่อคำขอนัดหมายได้รับการอนุมัติ (Confirmed) ระบบต้องทำการล็อกช่วงเวลาดังกล่าวทันที เพื่อป้องกันไม่ให้มีนักศึกษาคนอื่นยื่นคำขอนัดหมายซ้ำซ้อนในเวลาเดียวกัน | FR-01, FR-03, NFR-04 |
