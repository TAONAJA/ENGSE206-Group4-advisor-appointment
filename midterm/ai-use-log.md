# AI Use Log — บันทึกการใช้ AI

- **กลุ่มที่:** [เลขกลุ่ม]

> บันทึกทุกครั้งที่ใช้ AI ในงานสอบนี้ เน้นคอลัมน์ "การตรวจสอบของมนุษย์"
> เพราะนี่คือสิ่งที่วัดว่ากลุ่มใช้ AI อย่างมีวิจารณญาณ

| ครั้งที่ | จุดประสงค์ | สรุปสิ่งที่ถาม AI | AI ตอบว่าอะไร | กลุ่มตรวจ/ตัดสินใจอย่างไร (เชื่อ/ไม่เชื่อ เพราะอะไร) |
|---|---|---|---|---|
| 1 | สัมภาษณ์ Stakeholder สวมบทบาทนักศึกษาพิการทางสายตา | สอบถามเกี่ยวกับปัญหาการใช้งาน Screen Reader และความต้องการระบบออฟไลน์ | AI ระบุปัญหาเรื่องขาด ARIA Label, Keyboard navigation สลับลำดับ และความต้องการระบบเซฟร่างคำขอ (Offline Draft) พร้อมดูข้อมูลนัดหมายแบบออฟไลน์ | เชื่อ: เนื่องจากตรงกับมาตรฐานการออกแบบเว็บ Accessibility (WCAG 2.1) และหลักการทำงานของ Progressive Web Apps (PWA) ในชีวิตประจำวันจริง |
| 2 | สัมภาษณ์เรื่องมาตรการความปลอดภัยของระบบออฟไลน์ | สอบถามว่าระบบ Offline Sync จำเป็นต้องมีมาตรการความปลอดภัยระดับใด | AI ตอบว่าจำเป็นต้องใช้ Military-grade Security Protocol ในการส่งและซิงก์ข้อมูลออฟไลน์เพื่อป้องกันข้อมูลนัดหมายรั่วไหล | ไม่เชื่อ: เนื่องจากเป็นการระบุคำที่เกินจริง (AI แต่ง) ระบบเว็บแอปพลิเคชันทั่วไปใช้มาตรฐาน HTTPS ร่วมกับ Local IndexedDB/Web Crypto API ก็เพียงพอต่อความปลอดภัยของข้อมูลการนัดหมายแล้ว |
| 3 | สอบถามเรื่องการประมวลผลเอกสารแนบแบบออฟไลน์ | ถามว่าควรรองรับการอ่านเล่มโครงงาน PDF แบบออฟไลน์อย่างไรสำหรับผู้พิการทางสายตา | AI เสนอให้สร้างเอนจิน AI สำหรับแปลงไฟล์ PDF เป็นไฟล์เสียงและเบรลล์แบบออฟไลน์ฝังไว้ในตัวระบบ | ไม่เชื่อ: ซับซ้อนเกินจำเป็นและกระทบต่อข้อจำกัดด้านงบประมาณ/เวลาเดิม ควรใช้ Screen Reader มาตรฐานบนอุปกรณ์ของผู้ใช้ |

## สรุปข้อมูลที่ AI "แต่ง" ให้และกลุ่มไม่เชื่อ
> เช่น ตัวเลข performance, สถิติ, นโยบายที่ AI สร้างขึ้นเองโดยไม่มีที่มา

- ข้อกำหนด Military-grade Security Protocol: AI สร้างเงื่อนไขความปลอดภัยที่เกินความจำเป็นสำหรับระบบนัดหมายเข้าพบอาจารย์ กลุ่มจึงตัดสินใจใช้นโยบายการเข้ารหัสมาตรฐาน Web Cryptography API บนเบราว์เซอร์แทน
